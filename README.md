# ghpk — GitHub Packet Manager

Установка и обновление DEB-пакетов из GitHub Releases. Список программ хранится в JSON.

```bash
ghpk install storytold/wordcraft https://github.com/storytold/filmcraft
ghpk update
ghpk upgrade
```

## Установка

Склонируйте этот репозиторий или распакуйте архив и откройте папку с `install.sh`:

```bash
sudo apt install python3 python3-tqdm
sudo sh install.sh
```

Запускайте `ghpk` без `sudo`: права запрашиваются только при передаче пакета APT. Программа не использует `pip` и виртуальные окружения.

## Команды

| Команда | Действие |
| --- | --- |
| `ghpk install REPO [REPO ...]` | Получить последний стабильный релиз, установить DEB и сохранить репозиторий в список |
| `ghpk update` | Обновить сведения о релизах всех включённых репозиториев; ничего не устанавливать |
| `ghpk upgrade` | Установить версии из кэша последнего `update` |

Поддерживаются `автор/репозиторий`, `https://github.com/автор/репозиторий` и ссылки с `.git`. Репозитории передаются через пробел; повторы игнорируются. Если установка одного пакета завершилась ошибкой, остальные обрабатываются дальше. Код выхода при любой ошибке — `1`, при неверной команде — `2`.

`update` выводит число доступных обновлений, сравнивая тег релиза (без начального `v`) с установленной версией по правилам dpkg. Если пакет не определён или тег не похож на версию, результат учитывается отдельно как неопределённый. Точная версия DEB проверяется при `upgrade`.

Повторная установка той же версии пропускается. Понижение версии не выполняется. Уже установленные через DEB программы переустанавливать не требуется: `install` проверит версию и зарегистрирует репозиторий.

Установленные приложения запускаются из обычного меню, если автор DEB включил ярлык. Консольные утилиты запускаются своей командой. ghpk отвечает за установку и обновления, а не за запуск приложений.

## Список программ

`~/.config/ghpk/repos.json` создаётся после первой успешной установки. Можно редактировать вручную:

```json
{
  "repos": [
    {"repo": "storytold/wordcraft"},
    {"repo": "storytold/filmcraft"},
    {
      "repo": "rustdesk/rustdesk",
      "asset": "^rustdesk-[0-9].*-x86_64\\.deb$",
      "package": "rustdesk",
      "enabled": true
    }
  ]
}
```

- `repo` — обязательный адрес репозитория.
- `asset` — регулярное выражение для имени DEB. Нужно, если релиз содержит несколько подходящих пакетов.
- `package` — ожидаемое имя Debian-пакета. Заполняется автоматически после установки; можно задать для дополнительной проверки.
- `enabled: false` — исключить запись из `update` и `upgrade`. Явный `install` снова включает её.

После изменения списка или фильтра выполните `ghpk update`, затем `ghpk upgrade`. Удаление записи прекращает отслеживание, но не удаляет установленную программу. Для удаления пакета используйте `sudo apt remove ИМЯ_ПАКЕТА`.

Поддерживаются `XDG_CONFIG_HOME` и `XDG_CACHE_HOME`. Кэш релизов, состояние установок и блокировка находятся в `~/.cache/ghpk/`.

## Какие репозитории подходят

Любые публичные GitHub-репозитории с готовым DEB в последнем стабильном Release. Встроенного каталога или привязки к Storytold нет.

Архитектура определяется через `dpkg`: распознаются `amd64`/`x86_64`/`x64`, `arm64`/`aarch64`, `armhf`/`armv7`, `i386`/`i686`/`x86`, `riscv64`, а также `all`/`noarch`. Если архитектуры в имени нет, допускается единственный подходящий DEB. Перед установкой архитектура и имя проверяются по метаданным самого пакета. Совместимость зависимостей проверяет APT.

SHA256 берётся из GitHub API. Если поле отсутствует, используются файлы релиза `SHA256SUMS`, `SHA256SUMS.txt`, `checksums.txt` и аналогичные, либо `<имя.deb>.sha256`/`.sha256sum`. Поддерживаются GNU- и BSD-форматы. При отсутствии однозначной суммы установка останавливается. Контрольная сумма проверяет целостность; отдельной проверки подписи издателя нет.

WordCraft и FilmCraft выбираются автоматически. У RustDesk несколько DEB для одной архитектуры — используйте фильтр из примера. Состав файлов в релизах может меняться.

Не поддерживаются RPM, AppImage, сборка из исходников, приватные репозитории, prerelease и произвольные GitLab/Gitea-серверы. Обычные APT-репозитории добавляйте средствами APT; `apt upgrade` не обновляет кэш ghpk.

При ограничении GitHub API можно задать токен в переменной `GITHUB_TOKEN`. Не записывайте токен в `repos.json`. Токен передаётся только запросам к API GitHub.

## Удаление ghpk

```bash
sudo rm -f /usr/local/bin/ghpk
sudo rm -rf /usr/local/lib/ghpk
rm -rf ~/.config/ghpk ~/.cache/ghpk
```

Установленные DEB-пакеты при этом сохраняются.

## Разработка

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тесты не требуют сети и не устанавливают программы. Модули: `cli.py` — команды, `github.py` — релизы и выбор файлов, `packages.py` — проверка и установка DEB, `storage.py` — конфигурация и состояние, `ui.py` — сообщения и tqdm.
